# Grade a cross-checkout continuation

From the plugin root, run `node examples/continuation/checkout-trial.mjs` in a terminal. It creates four independent temporary projects from the fictional Signal Yard records. The fixture terminal owns setup and cleanup. Leave it open. Each path ends in `Workshop Project`. Keep this grader, the fixture generator and the printed case labels outside the readers' material.

For each path give a **fresh reader** the mechanism CAD skill entry point and the ordinary request **What should we try next?** Supply only the project path. The reader follows the skill and its guide, works read-only and records the relative paths and revisions actually opened. Capture the full answer and access history. A different experiment is acceptable if it distinguishes the same outstanding decision.

| Case printed to grader | Required discovery | What the recommendation must do |
|---|---|---|
| unmounted | Open `review-violet:notes/05-review.md` on the unmounted branch. Record its commit and heading. On main, read the D4 candidate, archived D1 proposal and limited B4 bench evidence. | Try loaded straight entry with a centered and offset pass. Explain why the archived scoop is historical and loaded transfer remains open. |
| correction | Open `notes/05-review.md` in the registered **Workshop Notes** worktree. Report its worktree path, modified status and owner correction. The committed copy selects straight entry. | Change the next trial to a loaded corner pass and vary the oblique approach. Citing the correction while recommending straight entry fails. |
| conflict | Resolve both local proposal refs to commits and read `notes/06-options.md` on each. Main's session 03 defers selection. | Explain the two equal proposals. Prepare common plane/orientation observations and ask which pass to prioritize. |
| plain | Read the records in the plain folder, including session 03. It contains no selection. | Name the unresolved choice, propose shared setup, and ask the single priority question. |

Record discovery, decision and workspace preservation separately. Use the Y1 rule, current candidate, cycle and original bench result to bound the advice. Before and after each reader, run `node examples/continuation/checkout-trial.mjs snapshot "<printed project path>"` and compare the JSON. It captures HEAD, branches, refs, index entries, registered worktrees, status, and hashes of tracked and untracked content, including dirty corrections. Enter `finish` in the fixture terminal after all four trials. It verifies the in-memory baselines before removing its own four directories. An interrupted or changed exercise retains its temporary directories for inspection.
