# Acquired season slices: candidate integration

This separate candidate adds `scripts/run-acquiring-robot.py` followed by `scripts/acquiring-robot-targets.py --receipt <fresh-run>/receipt.json --output <new-file>`. It does not modify the handoff-ready prototype entry point. Existing JDK17 and populated WPILib2026.2.1 cache are required; no installs occur.

Four fresh Java cases acquire the final20mm approach, ideally retain at exact rest, drive the existing kinematic approach and execute the existing pregrip/guide model. The receipt binds source/test inventory, actual loaded class hashes, motor JAR, Java executable, unique run ID and XML plus a separately resolved runtime/test/native dependency artifact manifest. Acquisition and motor residuals are separate. The target adapter checks acquired rest, pitch/mass, independently reconstructed impact ledger, generated pose/velocity and acquisition+robot clock before using existing finite-body target evaluators. It rejects missing/stale dependencies, duplicate/malformed records, nonfinite values and changed handoff states. A stored report reproduces recorded execution; only the fresh runner executes Java anew.

At the nominal12V refined settings, NOTE and FUEL pass their declared conditional whole-body thin-plane checks; both CORAL mass cases conditionally stop inside the isolated floor patch only for hypothetical mu0.3/0.5. Mu0/0.1 controls remain failures. These are model outcomes, not official scores.

Scope is deliberately narrow: incoming0.6m/s is externally prescribed, not a simulated human station or floor pickup. Same-pitch guide gravity is included. The instantaneous inelastic impact dissipates known energy and applies a reported impulse; it is not a finite bumper/load model. Ideal latch is mapped to closed pregrip gate and its existing after-grip opening sequence. Physical latch release geometry is unknown. Body center remains fixed in the guide frame during ideal rigid carry. Drivetrain energy, acceleration disturbances, spin, compliance and full field collisions are unmodeled; the separate acquisition/motor ledgers do not claim whole-robot energy conservation. Calibration, physical acceptance and official score remain unset.

Fresh native Java verification covered four tests including all four nominal masses, source failure/replay rejection and drive faults. Python checks separately reconstruct source ledger and target continuity. Low-supply and heavy-inertia failures remain in the previous reviewed prototypes, not replaced by this four-case12V candidate.
