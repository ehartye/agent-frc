# Link abstract comparison evidence into the decision chain

This adapter links **hypothetical verification** into the existing graph without fabricating a subsystem specification, approved design, measured inventory or real match score.

```sh
npm run --silent compare:link -- case-studies/2026/envelope-study.json case-studies/2026/comparison-experiment.json case-studies/2026/field-package.json
```

The CLI executes the bounded local abstract benchmark, then prints `{study, receipt}`. It does not overwrite a file, install anything, publish or operate hardware. Save outputs outside the public repository if they contain real team data. The CLI expects `game-2026` and `resources-2026`; the exported `executeAndLinkComparison` accepts explicit artifact IDs and a unique prefix. At most 256 runs can be linked per cohort.

## Record types

- **comparison-input:** one independently revisioned hypothetical concept, policy, scenario or simulator model. Each pins the exact existing Game Analysis and Resource Baseline. Parameters and hashes are preserved. These concepts are abstract assumptions, not assertions that any existing preliminary envelope has been simulated.
- **comparison-experiment:** a full configuration, its SHA-256, model/runtime pin, source-field package hash, linker-source hash, and explicit bindings to each input. This is a controlled comparison join: only this kind may read sibling `comparison-input` records. Ordinary design/subsystem artifacts retain their branch isolation.
- **comparison-run-evidence:** one actual local execution outcome, its manifest/run ID, outcome hash and trace hash, plus the exact experiment/config/linker pins. The run remains hypothetical. Raw released-piece counts do not become scoring, conditional fuel points or hardware evidence.

All current run records enforce null score/win probability and unassessed physical reachability. They retain full hypothetical assumptions and model limitations. A future source-grounded scoring-event adapter needs its own explicitly reviewed evidence semantics; do not relabel these records.

## Source and change impact

The adapter requires the selected Game Analysis to pin the exact field package hash and field model used by the experiment. The resource baseline must use the explicit resource schema, and relevant baseline revisions must not already be stale. It executes locally instead of accepting a caller-provided successful receipt.

Changes to rules/field analysis, resources, scenario, concept, policy or model mark the bound experiment and every run in that cohort stale. This conservative cohort invalidation is intentional: no partial cohort is silently reported as a current fair comparison. Existing envelopes/strategies are not replaced or selected. Future changes on disk are not automatically discovered by a stored graph; ingest a new source/model artifact revision and run the impact report.

Changing or re-pinning an experiment does not rerun its evidence. Old run content contains its original experiment/config/linker pins; simply replacing its dependency reference fails validation. Use a fresh unique prefix to execute a new cohort. Preserve prior artifacts for audit.

## Evidence and replay limits

The receipt names each run artifact and contains config, field, model, linker and outcome hashes. Full traces are generated in memory and checked against their hashes, but are not duplicated in the graph. Replay requires the exact configuration, source/model versions and Node runtime. Hashes prove consistency, not source authenticity, trusted authorship or a human team decision.

Graph validity/freshness is not rule completeness, calibrated physics, legal eligibility, reachability or hardware safety. No strategy decision API is introduced. No simulation results are claimed for actual kit ownership or the preliminary robot-envelope candidates.

`case-studies/2026/comparison-chain-validation.json` records the full 144-run linkage smoke test: 162 graph artifacts, zero stale heads at execution, exact study/experiment/linker/model/config/field/outcome digests and no selected candidate. The complete graph can be regenerated by the CLI rather than duplicating every run manifest in the repository.

For explicitly supplied hypothetical passage events, use [scenario-level FUEL annotations](fuel-scenario-annotation.md). This separate evidence type preserves unsupported/null assessment and exact source/context dependencies; comparison-run scores remain null.
