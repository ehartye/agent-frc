# Check the actual object after the holder opens

An empty mechanism can reach every commanded pose while a released piece strikes the fixed frame below it. Follow one finite physical piece from its admitted position through approach, release, departure and its intended receiving region. Compare a credible jam and the complete recovery to a known ready state.

Run `python scripts/loaded_transfer.py PROJECT loaded-study.json`. The study schema is `agent-frc/loaded-transfer@1`. Supply the project-owned current STEP, an `id` and duty `basis`, gravity in mm/s², a trace tolerance in mm and `piece:{id,file,solid}` with the complete piece's pinned STEP. Each case has a unique `id`, `duty` (delivery or jam-reset), a measured `admissionGapMm` maximum against the physical holder, a frozen two-element `windowS`, the expected `terminalBoundsMm` in the CAD frame, and a pinned `trace`. Bounds use [minimum X,Y,Z, maximum X,Y,Z].

The actual trace identifies the same case, STEP and piece SHA-256, physical `pieceId`, installed `holder` solid and source. Each frame has its executed `timeS`, `custody` and `offsetsMm` mapping the physical piece and each translated moving member to its millimetre displacement from registered geometry. Keep the full installed assembly as a collision obstacle. List adjacent finite pieces or fixtures in `stock` with separate physical IDs, actual pinned `file`, `solid`, `offsetMm` and `basis`. The original trace gives the same `stockIds`; every registered remaining item stays in the checked geometry. Held and recovery translations are linear within an observed interval. A `free` interval starts from rest in the downward Z direction and follows the declared gravitational acceleration. The solver checks the later positions against that motion and computes a conservative bound on intermediate travel. A released, contact-guided trace uses `guided`, a named installed `guide`, pinned original `trajectorySource` and `interpolationBasis`. Use a finer recorded path or a supported trajectory solver where linear interpolation cannot describe the actual motion. Rotating cargo and unsupported dynamics require an independently bounded full-motion check; they cannot claim this translation-only result.

A successful delivery ends with `received` and the entire named object inside the registered receiving region. A recovery includes `jammed`, ends with `recovery`, identifies the measured rearm using `resetObserved:true` and `readyOffsetsMm` for every moving installed member, and must return the object to the registered region within the declared clock. Explicitly register qualified intentional interfaces by segment index in `interfaces`. A passed opening, empty return, or a different object reaching a station cannot close this duty. Preserve one fixed bridge crossing the released object’s route plus a corrected matched case. An intentionally blocked jam retains its independent consequence and recovery evidence.

Include the relevant physical handoff IDs in the independent reopen record’s `transferMissions` and map each ID to its pinned study in the readiness issue’s `transferClaims`. A project with no transfer in scope uses an empty list and map. Review scope against the selected robot role before approving these declarations. This process checks mechanical clearance and delivery in the stated model. Match scoring requires separate rule- and actor-bound evidence.
