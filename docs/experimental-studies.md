# Experimental studies and verification scope

The strategy, contact, retention, acquisition and target studies are preserved exploratory implementations. Their checked-in receipts describe particular historical source and runtime identities. Integrating the implementations does not renew those receipts or establish physical acceptance.

## Current portable checks

Run `npm test` and `npm run validate` from the repository root. The original integration checkpoint passed 273 Node tests; the verification/diagnostics implementation subsequently passed 295, including the new historical-runner and skill-parser tests. Validation checks ten skills and both compatibility manifests. Use the actual runner output for the current count. These portable checks do not execute Python studies or Java/native experiments.

The [historical verification guide](historical-verification.md) provides a separate executable route for one reviewed case, `acquisition-contract`. Preflight reports prerequisites; explicit execution with a selected existing interpreter reconstructs seven exact Git blobs and runs six pinned Python tests. The case was exercised with Python 3.13.12, including a fresh public-origin clone. That bounded result does not renew other receipts.

## Historical and native checks

The Python `scripts/test-*.py` files include tests that reproduce historical receipts or require separately obtained native geometry. The existing Python npm commands are [working-tree study checks](historical-verification.md#existing-working-tree-python-studies); their behavior is unchanged. Running every file against one current checkout is not a supported all-green regression command: several receipts deliberately pin earlier versions of shared source and `build.gradle`.

An integration audit ran 56 Python test files: 33 passed and 23 failed. The failures reported historical source/runtime hash mismatches or unavailable native inputs. They remain failures, not skips or renewed evidence. In particular, tests for acquisition, catcher supervision, integrated prototypes, season handoffs and powered targets cannot certify the current combined source from their old receipts. The MAXLift and retained-pregrip native tests require their documented supplier geometry; wheel extraction requires an explicitly selected `FRC_WHEEL_STEP`.

For a fresh experiment, select its documented runtime and inputs: Java experiments need an existing compatible JDK and populated WPILib cache; native studies need their documented geometry. Run into a new output directory and preserve complete dependency inventory, runtime classes, logs and negative controls. Do not overwrite an old receipt or replace its hashes with current values. For historical acquisition evidence, use [the bounded reconstruction command](historical-verification.md); it needs neither a JDK nor native inputs. Other cases still require separately reviewed reconstruction under [the historical verification principles](simulator-equivalence.md#current-tests-and-historical-evidence-are-different-questions).

No fresh Java/native trajectory replay, hardware calibration, whole-robot acceptance or robot deployment is claimed by this integration. The library and example code remain available for bounded experiments with explicit source and environment requirements.
