# Could the robot reach this scoring event?

A detector can register a piece even if an earlier command drove the simulated robot through a wall. Record what the detector saw. Check the occupied route from the start of the mission to the event before using that event to compare strategies.

Start with the installed field inventory. Two files generated by the same route producer can agree after both omit an obstacle. Independently enumerate the source collections and compare them to each route interval. The [invented fixture](../examples/field-route/make-example.mjs) includes a field catalog, a separate inventory declaration and a preloaded piece.

```sh
node examples/field-route/make-example.mjs artifacts/route-example
npm run field:route -- artifacts/route-example/request.json
```

The example checks an invented carriage and parcel passing a post. All dimensions are metres and times are seconds on one clock. Each six-number box gives minimum X, Y, Z followed by maximum X, Y, Z in the installed field frame.

Each detector, swept-enclosure or refinement document includes a `sourceEvidence` file reference and SHA-256. Keep the original observations, trajectory bounds or native solver output so a reviewer can reproduce or challenge the reported figures.

| Project file | What to record |
|---|---|
| Scenario | Pin the field, robot, transform and trajectory files by SHA-256. Name every robot body, placed obstacle and piece. Set the mission start, clearance margin and nonoverlapping time intervals. Split at each change in carried inventory and at scoring observations where possible. |
| Detector | Bind the scenario digest and clock. Give each observed event a distinct ID, piece and time. Preserve the original detector evidence and distinguish one continuous occupancy from a new entry. Apply the project's actual scoring rules separately. |
| Swept enclosures | Bind the same scenario and clock. Give continuous field-frame bounds covering every expected moving body, carried piece and obstacle for each full interval. Include moving obstacles over that time. Endpoint boxes alone can miss a collision during rotation or articulation. |
| Refinement | For overlapping bounds, attach a pinned JSON record with the scenario digest, clock, backend, moving body, obstacle, interval and method. A continuous lower bound above the margin clears the pair. A measured positive material intersection above tolerance records the time, pair and volume. An unexamined part of an interval keeps the result pending. |

Use `continuous-lower-bound` with `minGapM` for a complete pair interval, or `material-intersection` with `timeS`, `volumeMm3` and `toleranceMm3`. For intentional compliant contact, declare the pair and limits in the scenario's `contactResponses`. Supply a `coupled-contact-response` refinement with the same trajectory digest, a pinned `dynamicsEvidence` file, a named `contactModel`, `completeInterval`, `continuationIntegrated`, and the measured `maxPenetrationM` and `maxResidualM`. Review the external solver and verify that its response actually produced the later trajectory.

The result retains every detector event and reports its route as supported, pending or infeasible. It lists missing registration, unresolved intervals and identified contacts. A collision on a later leg leaves an earlier verified event intact. Review the producers' geometry, transforms, time coverage and detector calibration before using their bounds. ## Reconcile starting occupancy

Add a pinned `inventory` reference to the request. Use `field-route/inventory@1`, the field's exact `fieldSha256`, the scenario clock and `startS`. Name the scope as `whole-field` or `bounded-study` and list unresolved categories in `scope.unresolved`. List intentionally out-of-scope categories in `scope.outsideScope` for bounded studies. Unknown objects within the study keep support pending. A supported bounded study leaves `wholeFieldStatus` pending.

Each entry in `collections` selects a complete collection from the pinned field JSON using a list of object keys in `path`. Select arrays of IDs with `format: "ids"`, dictionary keys with `"keys"`, or an array of records with `"rows"` and `idKey`. Set `initial` to `placed`, `carried`, `stock` or `unknown`. If the collection has registered boxes in the installed frame and metres, use `bounds: "value"` on a dictionary of boxes, or specify the box field name. Each swept obstacle must enclose its registered initial box until a documented move. For native CAD, supply a pinned inventory `export` containing its parent `fieldSha256` and the source-derived collections.

For a whole-field claim the field catalog or bound export must itself include `fieldRouteInventory` with `complete: true`, an empty `unresolved` array and the authoritative `collections`. The checker requires the complete selection. The team's source review establishes that the catalog actually inventories the installed field. A bounded study can select a named subset without modifying the source.

Split intervals at changes of custody or position. Use the scenario's `obstacles` for its possible field IDs, and each interval's `obstacles` and `carried` for the active IDs. Keep identities stable when a piece leaves stock, moves onto the field, is carried, and becomes a placed obstacle again. Add pinned `transitions` with schema `field-route/state-change@1`, `id`, `from`, `to`, `timeS`, `method`, field and trajectory digests, clock and pinned `sourceEvidence`. A placed destination requires its new `bounds`. An object physically removed uses `removed`. A producer can exclude a known placed object for an interval using a pinned `field-route/exclusion@1` in `exclusions` with the same bindings, `id`, `fromS`, `toS`, method `continuous-lower-bound`, and `minGapM` above the required margin over the entire interval. A free-text rationale alone leaves occupancy unresolved.

Older requests still expose their declared-body result in `declaredRouteStatus`. Independent `routeStatus` stays pending when starting occupancy is unverified. Confirmed material interference can still rule out the route. Read `inventoryGaps` for the identities and times needing attention.

### Check which installation a collision describes

At the witness time, the obstacle must still be placed and the swept bounds must enclose its registered bounds. A moving game piece must be in the carried state. A state change takes effect at its recorded instant. An unresolved contact stays in `contacts` with its `registrationIssue`. Read `qualifiedContacts` for the witnesses that apply to the route. A matching collision can reject the route even when coverage elsewhere is incomplete.

Different solids or orientations can share an outer box. In this case use a source collection of records and set `geometryKey` to the property holding the SHA-256 of each installed occurrence's geometry and placement record. Put that same digest in `obstacleGeometrySha256` on its material witness. Supply `geometrySha256` when a transition places that occurrence again. The project owns the source record, including the local shape, transform and units that identify the installation.

## Observe the robot reaching a region

Run the synthetic carriage through a field with one column and an empty game-piece list.

```sh
node examples/field-route/make-body-example.mjs artifacts/body-route
npm run field:route -- artifacts/body-route/request.json
```

Use a detector event with an `id`, `robotBody` and `timeS`. Piece observations use their existing `piece` property. For a body event, point the scenario’s robot source at a `field-route/robot@1` JSON manifest. Its `geometry` and `catalog` identify pinned project files. Its `collection` selects the complete body list from that catalog using the same `path` and `ids`, `keys` or `rows` format as field inventory. Every listed body needs sweep coverage. Use `scope: "subassembly"` for an isolated mechanism. A supported subassembly route leaves whole-field robot qualification pending.

The detector’s `sourceEvidence` names a `field-route/body-observations@1` journal. Bind it to the scenario digest, geometry digest and clock. Each observation identifies the same body, event and time, describes the measured criterion, gives the numeric measurement’s unit in `unit`, and names a pinned JSON `measurement`. Its `path` selects a numeric field using an array of keys. The checker evaluates `above` or `at-most` against the project’s threshold and returns the value and source. For example, positive material volume in a region can record arrival. An observation at the deadline still requires continuous occupied-route evidence from the start. The project defines its geometry, measurement units, detector and scoring rule. [Complete working example](../examples/field-route/make-body-example.mjs)
