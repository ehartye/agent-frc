# Original season roller CAD prototypes

This is executable native CAD generation/extraction for proposed mechanism sleeves, not an executable whole robot or a scoring simulation. The two initial candidates are distinct: a flat NOTE between 101.6 mm diameter, 400 mm span opposed sleeves; and axial CORAL between 50.8 mm diameter, 152.4 mm span sleeves. Both have 12.7 mm bores. Dimensions of the sleeves, 1:1 gearing, one motor per sleeve and uniform 1200 kg/m³ density are explicit original design assumptions, not manufacturer specifications or validated motor selections.

The right-handed frame uses X transport, Y shaft, Z up. Nominal surface gaps use reviewed piece thickness/diameter: 50.8 mm NOTE and 114.3 mm CORAL. Positive shaft rotation about +Y gives negative-X surface motion on the upper sleeve and positive-X on the lower. Nominal tangency prescribes no compression or normal force. Friction and normal force remain null in these CAD inputs. A later experiment must explicitly declare any assumed contact parameters, and may not claim calibration.

The NOTE is a foam torus, not a filled disk. Its center hole changes contact/support; sleeve span exceeding outer diameter does not ensure grip or alignment. CORAL is a finite hollow tube with curved surface contact, not a point mass or solid cylinder. These native artifacts contain only two rotor sleeves. They omit game-piece deformation/contact, shafts, motor/gear inertia, bearings, couplers, support structure, guards and installation. The computed mass/inertia belongs only to each original ideal sleeve under assumed uniform density; it is not complete mechanism or robot mass.

`python scripts/season-mechanism-cad.py case-studies/2024/roller-mechanism.json NEW_OUTPUT_DIRECTORY` creates native STEP, reads the STEP back, selects exactly one solid per explicit bound, extracts native volume/centroid/tensor and computes shaft inertia with the perpendicular parallel-axis term. The output directory must be new; a failed run records failed status rather than reusing success. Repeat with the 2025 configuration. The output retains original config bytes, exact STEP/property/source hashes, OCP/Python runtime and blocked acceptance. The STEP writer can embed changing header metadata: pin each actual produced file, not an assumed cross-run STEP hash.

`python scripts/test-season-mechanism-cad.py` independently checks native round trips against analytic annular-cylinder properties, perpendicular-axis offsets, both distinct candidates, mismatched bodies, invalid provenance/physical unknowns and retained receipts. Native CAD execution is separate from Java IO and from Node planning tests. OCP is required; missing native dependencies fail, never count as skipped success. No installation or hardware operation is part of this command.

Exact strategy/envelope/contract/subsystem pins are checked against the current per-season planning graph. Source hashes identify the reviewed manual snapshot, not source authenticity. A changed case/graph must be reviewed and repinned explicitly. The fixture datums and sensor planes are not field targets; no exit or beam event is a score. The later IO owner must consume these exact input/property/STEP bytes and independently bind actual code, actuator/sensor conversion, motor profile, scenario and contact assumptions. All engineering acceptance remains blocked, including unresolved thermal, friction and complete weight-distribution evidence.
