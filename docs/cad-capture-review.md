# Verify a saved CAD still

A student should be able to recognize the same assembly, configuration and pose in the Fusion source, the still and the design review. A successful PNG write, matching hash or set of visible body flags can coexist with an empty viewport or an earlier assembly drawing. Inspect the pixels in the delivered image.

## Capture the intended document

1. Record the selected archive or STEP hash, version, assembly pose, camera, intended visible groups and what the title promises. A frame service view may intentionally hide most of the robot. A robot overview needs the installed exterior. Identify visible mechanism members, cover finish and readable lettering when those are part of the claim.
2. Reopen the **saved archive** in an owned document. Activate that document, the intended design/root component and the intended timeline position. Confirm identity immediately before capture. Inspect parent occurrence and body-folder visibility, bodies, isolation, opacity and the effective per-occurrence graphics state. Keep hidden references, alternate candidates and fixtures hidden where the selected view calls for it.
3. In the owned display document, apply the selected representation. If a freshly opened viewport looks incomplete, invalidate and restore the **intended** display groups, process pending graphics events, refresh and fit the intended camera. Re-read the resulting eye, target, up, extents and pixel dimensions. Keep the failing image. Never count a successful refresh or a delay as evidence that the new pixels are correct.
4. Inspect the PNG at student reading size. Compare the outline and one or more discriminating features against a known view of the exact source. A missing crossmember can leave the outline largely intact. Inspect both the ink strokes and the negative spaces between characters if the page promises readable markings. Separate a fresh native viewport from an archive’s embedded preview and from a STEP-derived render. Each can use a different camera. Preserve the screenshot or render actually verified.
5. Link the verified still and its specific configuration to the design review. Keep a separately issued engineering revision under its own caption until its own capture and handoff are ready. Close only the documents opened for this check.

## Check a registered view

The teaching fixture compares a real saved preview with the active-design PNG inside its Fusion archive. The full silhouette and lower wheel/fork region are registered independently. Run the optional pixel check with Python and Pillow (9.1 or later).

```sh
python scripts/cad_capture.py . examples/swerve/capture-review.json
```

Use the [teaching manifest](../examples/swerve/capture-review.json) for the file layout. The project owns the pose, registration basis, features and tolerances. Each file reference supplies its project-relative `file` and SHA-256 of the exact bytes. Both the submitted image and the reference must be PNGs. For newer Fusion archives, Python 3.14 supports ZIP Zstandard previews. A separate compatible interpreter may be supplied through `FRC_ARCHIVE_PYTHON` if the Pillow interpreter cannot open that compression method.

- **Embedded Fusion preview.** Use `reference.kind: "archive-preview"`, with the archive itself as the source. The checker reads the active design’s `Previews/big.png` entry. Set `requireExactCopy: true` when the published image is advertised as the original preview. Examine the embedded picture first: a stale or blank embedded picture is a poor visual reference.
- **Verified render or independent native capture.** Select `reference.kind: "verified-render"`, with `receipt` and `image` file references and the `sourceDigestPointer` and `imageDigestPointer` JSON pointers in that receipt. For the plugin’s STEP renderer these are `/sourceSha256` and `/imageSha256`. Inspect the renderer, selected source, configuration, camera and visible landmarks before trusting its image. The receipt binds these file identities. A diagnostic projector using a different viewpoint needs its own matching reference. Register comparable projections before comparing screen-space masks.
- **Witnesses.** Each feature has a unique ID, kind (silhouette, component or marking), normalized `referenceRegion` in left/top/right/bottom order, and an RGBA range. For a transparent background select opaque pixels. With a known light background a project can invert a background range. Use separate `candidateRegion` or `candidateSelector` only for a documented crop, scale or presentation change that preserves the physical projection. Include the object's surrounding gaps in the crop. Test the full printed marking and inspect the actual characters against the intended source artwork. A total count of light pixels can remain constant when the printed characters change.
- **Decision.** `referenceCoverage` gives the project’s acceptable occupied fraction for this feature in the known view. The whole cohort of parts in a different camera may have very different fractions. `minIoU` compares the intersection of selected pixels with their union in registered coordinates. Equal foreground area with a different pattern lowers that overlap. A reference with no useful feature opens the check. A changed feature below its project threshold fails. Choose a grid that resolves the smallest promised stroke and exercise a deliberately missing or wrong part. Lighting, antialiasing, perspective and occlusion limit transfer between views.

To apply the check to the standard README workflow, point `captureReview` in `cad-showcase.json` at the project-owned manifest. The README checker binds it to the same selected CAD source and published PNG as its export receipt. The highlights builder honors that setting when it publishes the same assembly. A separately registered historical `cad` model may specify its own `captureReview`. Run standalone for an archive-based view whose CAD source differs from the standard STEP receipt. A pass covers only the named visible features; rotational replay, hidden shape and unobserved faces require separate evidence.
