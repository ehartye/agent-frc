# Qualify the model students will build

Run this review before promoting new robot CAD to a showcase, README or downloadable student assembly. Keep a failed candidate in the team project. A failed build leaves the last successful deployment serving its previous revision. A game analysis or field lab can appear independently of a robot model.

## Start with the actual installed assembly

Register the [authoritative Fusion design and current native revision](fusion-authority.md). Choose the exact configuration, revision and operating scope. Review a subsystem as a subsystem and identify its outside interfaces. Cold-reopen the saved Fusion archive, export its complete placed STEP and collect a native observation independent of the design BOM. Resolve file identities before calculating distances. A simplified intake envelope, a hardware catalog number and a screenshot each answer different questions from the exact installed part.

Run [the complete Fusion body census](../scripts/fusion_issue_inventory.py) inside Fusion. Choose the exact archive and a fresh receipt. The script opens its own document, traverses the root and every occurrence including hidden bodies, records body identity, display state, bounds and pose, then restores the previous document. Pin this result as `nativeCensus`. Its complete pair table compares native Fusion interference with an independently placed temporary-solid intersection. Each positive common volume needs a pair-specific, quantitatively bounded fit and human load-path review. The native scan checkpoints in measured pair batches. Resume the same archive, pose and output filename until the final receipt exists. Partial scans remain open. Register every critical moving pose in the reopen record’s `inspectionPoses`, including the saved pose, and pin each additional same-archive receipt in `nativePoses`. The continuous STEP sweep still covers travel between sampled native poses. Each reopen row maps its placed STEP solid identifiers to original Fusion body names in `nativeBodyNames`. The native occurrence path must match the census. Keep visible stock even if its name marks an earlier design. An unresolved surface, mesh or extra placed solid prevents qualification. Each purchased occurrence must match the complete set of solids in the official, configuration-specific source.

A manufactured part needs its editable Fusion design, controlled drawing, stock grade/temper and as-installed pose. Imported official CAD is acceptable for a purchased article. Check manufacturer, exact part number, hardware revision, chosen option, source bytes, native occurrence and license. For a standard fastener, include the evaluated material class, thread, length, fit, head and retention. An external neutral-to-Fusion workflow needs a recorded justification and reopen evidence. A manufacturer permitting rendered views may restrict public neutral or native downloads.

## Review the geometry and duties

1. Traverse the whole STEP assembly with placed occurrence transforms. Compute minimum distances between plausible neighbors and common solid volume between bounding boxes that can overlap. Inspect disconnected groups, including an isolated piece and an entire floating subassembly. A collision between a roller and an upright counts as interference even when its contact connects the geometry graph.
2. Name a chassis anchor and independently identify each retaining joint. Explain how its supported solids carry load through the installed hardware. Use a measured gap and a source-backed allowable gap for running clearances. Register an intended overlap against the specific pair and installed fit. A broad volume allowance for all fasteners can conceal an incorrectly seated head. A bearing load rating alone cannot establish an anchor.
3. Inspect endpoints and intermediate travel under tolerances and load. A continuous collision query or a conservative interval bound can cover unsampled positions. Record the actual independent motion groups, start/end configurations, approach, conservative bound and a deliberately interfering control. Test simultaneous movements whose relative paths can close. A handful of clear samples earns an open result until their gaps are bounded.
4. Select a shop and rebuild the most restrictive feature and joint from the drawing. Compare internal radius to the cutter, account for kerf and tolerance accumulation, access for clamping, cutting, torquing, assembly and withdrawal. For welded stock, check process capability, alloy and heat-affected properties, access, sequence and distortion. Record measurable stock, tooling, clearance and inspection limits. [Fabrication capabilities](fabrication-capabilities.md) · [Fabrication chain](fabrication-chain.md)
5. Freeze installed load cases before comparing alternatives. Check force and moment balance through the real load path, capacity of the governing member and attachment, deflection against functional clearance, credible impact energy/direction and repeated duty against an applicable life basis. Include uncertainty and sensitivity, and preserve results after damage or loss of one support. Identify simulation assumptions and outstanding physical qualification explicitly. ## Run the checker

Use file references of the form `{"file":"cad/issue.step","sha256":"…"}` relative to the project root. An observation reference adds an `id`. Freeze the exact inputs in a project-owned `agent-frc/mechanical-readiness@1` study. Python performs the portable review. Measurement and final model promotion require OpenCascade’s OCP bindings. The publication gate repeats the STEP scan and checks it against the registered geometry before writing public outputs. Generate a new scan when the STEP, attachment probes or contact tolerance change.

```sh
python scripts/mechanical_readiness.py measure PROJECT path/to/study.json --output PROJECT/geometry-new.json
python scripts/mechanical_readiness.py review PROJECT path/to/study.json --rescan
python scripts/mechanical_readiness.py review PROJECT path/to/study.json --require-publication --deliver cad/issue.glb
```

Pin the resulting scan in `geometry` after independent inspection. To use the built-in publishing paths, set `mechanicalReadiness` to the study path in the selected `cad-showcase.json` and public highlight CAD entry. A separately featured assembly supplies its own study, source, mesh, still and archive. A native-download-only page can set the field at the top of its highlights manifest. Custom Pages builders should review the candidate and pass every planned derivative through `--deliver` before uploading or replacing any output. Allow a failed check to stop deployment. Keep the previous issue accessible.

| Study field | Project evidence |
| --- | --- |
| `configuration`, `archive`, `step`, `reopen`, `geometry` | Exact F3D or F3Z, STEP, independent native observation and measured solid-pair report. `contactToleranceMm` controls near-contact reporting. `reopenBoundsToleranceMm` limits the native/STEP per-body world-bounds difference. |
| `articles`, `installed` | Articles keyed by ID have `id`, `kind`, `revision`, `configuration`, pinned `model`, `rights` and `rightsBasis`. Purchased entries require `manufacturer`, `partNumber`, `manufacturerSource` and `representation: "official-exact"`. Fabricated entries require a native model, controlled `drawing` and `materialGrade`. Source comparison also requires a pinned `neutral` model, a reviewed `shapeResolutionMm3`, and per-native-occurrence `sourceSolids` mapping placed solid names to exact neutral solid names. Give each occurrence its `neutralSha256`. The solver measures both missing and extra material at the installed rigid transform and rejects reflected placements. Expected occurrences use the native path as key and give `article` and a row-major 16-number world `transform`. |
| `chassisAnchor`, `connections`, `mating` | Choose a measured solid. A connection gives an exact solid `pair` and an `evidence` reference to a `retained-joint` observation with the same `pair`, `mechanism`, `loadPath`, `inspection`, `maxInterfaceGapMm` and observed `verified`. A fitted pair gives `pair`, `fit`, `maxMm3` and `evidence` to an `intended-fit` observation with the same values and a `basis`. All other positive rigid intersections fail. |
| `duties` | Each duty gives a unique `id`, `domain`, installed solid `subjects`, adverse `case`, `basis`, `unit`, `min` and/or `max`, and an `observation`. Cover sweep, shop, assembly, service, strength, stiffness, impact and fatigue. Register actual condition-specific engineering limits and fully scoped exemptions. |
| `coverage` | Independent `engineering` and `build` observation references. The scope reviewer identifies every installed body and all duties, including omissions. A narrow operating claim needs a narrow, honest scope. |
| `distribution` | Bind `configuration`, `archiveSha256`, `stepSha256`, `approvedBy` and pinned `files`. Each file also has `scope` (native, neutral, render or mesh) and an item-specific `rightsBasis`. Component rights may be `exact-redistribution`, `derived-views-only` or `private-master`. |

The native reopen gives `opened: true`, `configuration`, `archiveSha256`, `stepSha256`, `movingGroups` and `installedOccurrences`. Each occurrence gives `path`, `article`, `revision`, `configuration`, `modelSha256`, `worldTransform`, a list of `solids`, and a `worldBoundsMm` object keyed by those solids. Each bounds array contains minimum XYZ then maximum XYZ. Report native `editable` for fabricated articles. A component used four times needs four distinct installed paths.

Observation files bind the same configuration and both source hashes. Their `observations` are keyed by ID. Every observation cites the original pinned `sources`. Numeric observations repeat the duty ID, domain as `kind`, case, subjects, method, unit and value, with `measurement` pointing to an original JSON numeric value using a file, digest and JSON Pointer. Their `inputs` identify the engineering basis. Scope reviews use `kind: "scope-review"`, scope, reviewer, basis, complete flag, covered bodies and duties. The complete original numeric file uses `agent-frc/mechanical-measurements@1`, both source hashes, configuration and a `measurements` register. Each numeric result sits in a row that identifies the same duty, case, subjects and units. Every row of a cited case roster must be represented. For motion, report native `motionRanges` by group in the reopen and actual executed ranges and coverage in the raw result. The independent approval has `criteriaSha256` from the checker's `scope_digest(study)`; it freezes the occurrence assignments, cases, thresholds and source receipts. A reviewer must independently challenge whether all applicable cases are represented. A digest authenticates the bytes as selected by the project; it cannot independently validate a supplier specification or certify a person's approval.

The report returns geometry groups, retained groups, failed or open duties and their exact subjects. Visual inspection of the engineering model can continue when shop or structural evidence is incomplete. A new showcase model requires the full mechanical disposition. The gate assesses submitted evidence for the stated build and duty. It does not command a robot, authorize fabrication, or replace inspection of a physical assembly.
