## Review the geometry and duties

1. Traverse the whole STEP assembly with placed occurrence transforms. Compute minimum distances between plausible neighbors and common solid volume between bounding boxes that can overlap. Inspect disconnected groups, including an isolated piece and an entire floating subassembly. A collision between a roller and an upright counts as interference even when its contact connects the geometry graph.
2. Name a chassis anchor and independently identify each retaining joint. Explain how its supported solids carry load through the installed hardware. Use a measured gap and a source-backed allowable gap for running clearances. Register an intended overlap against the specific pair and installed fit. A broad volume allowance for all fasteners can conceal an incorrectly seated head. A bearing load rating alone cannot establish an anchor.
3. Inspect endpoints and intermediate travel under tolerances and load. A continuous collision query or a conservative interval bound can cover unsampled positions. Record the actual independent motion groups, start/end configurations, approach, conservative bound and a deliberately interfering control. Test simultaneous movements whose relative paths can close. A handful of clear samples earns an open result until their gaps are bounded.
4. Select a shop and rebuild the most restrictive feature and joint from the drawing. Compare internal radius to the cutter, account for kerf and tolerance accumulation, access for clamping, cutting, torquing, assembly and withdrawal. For welded stock, check process capability, alloy and heat-affected properties, access, sequence and distortion. Record measurable stock, tooling, clearance and inspection limits. [Fabrication capabilities](fabrication-capabilities.md) · [Fabrication chain](fabrication-chain.md)
5. Freeze installed load cases before comparing alternatives. Check force and moment balance through the real load path, capacity of the governing member and attachment, deflection against functional clearance, credible impact energy/direction and repeated duty against an applicable life basis. Include uncertainty and sensitivity, and preserve results after damage or loss of one support. Identify simulation assumptions and outstanding physical qualification explicitly. ## Run the checker

Name each file by its path relative to the project root, as `{"file":"cad/issue.step"}`. An observation reference adds an `id`. The review reads each named file and records the SHA-256 it read in the result. You type no hash. A `sha256` written beside a `file` is still verified, and a mismatch fails with `Changed evidence: FILE`, so a study that carries hashes keeps working. Keep the inputs in a project-owned `agent-frc/mechanical-readiness@1` study, committed with the files it names. Python performs the portable review. Measurement and final model promotion require OpenCascade’s OCP bindings. The publication gate repeats the STEP scan and checks it against the registered geometry before writing public outputs. Generate a new scan when the STEP, attachment probes or contact tolerance change.

```sh
python scripts/mechanical_readiness.py measure PROJECT path/to/study.json --output PROJECT/geometry-new.json
python scripts/mechanical_readiness.py review PROJECT path/to/study.json --rescan
python scripts/mechanical_readiness.py review PROJECT path/to/study.json --require-publication --output PROJECT/cad/detailed-design/readiness-result.json
```

Name the resulting scan in `geometry` after inspecting it. A results page that offers the Fusion archive for download sets `mechanicalReadiness` at the top of its highlights manifest. The design has [one published view, its design review](design-publication.md#one-viewer-for-one-design), so the review no longer checks a separate published mesh, still or animated model: `--deliver` is accepted and ignored.

Each bounds array contains minimum XYZ then maximum XYZ. Report native `editable` for fabricated articles. A component used four times needs four distinct installed paths.

Observation files bind the same configuration and both source hashes. Their `observations` are keyed by ID. Every observation cites the original pinned `sources`. Numeric observations repeat the duty ID, domain as `kind`, case, subjects, method, unit and value, with `measurement` pointing to an original JSON numeric value using a file, digest and JSON Pointer. Their `inputs` identify the engineering basis. Scope reviews use `kind: "scope-review"`, scope, reviewer, basis, complete flag, covered bodies and duties. The complete original numeric file uses `agent-frc/mechanical-measurements@1`, both source hashes, configuration and a `measurements` register. Each numeric result sits in a row that identifies the same duty, case, subjects and units. Every row of a cited case roster must be represented. For motion, report native `motionRanges` by group in the reopen and actual executed ranges and coverage in the raw result. A scope review lists every installed body and every duty it covered, and the review reconciles both lists with the study. It may also record `criteriaSha256`, the checker's `scope_digest(study)` at the time of the review. That digest is compared when present, and a study that changed since then reopens the scope; it is not required. A reviewer must still challenge whether all applicable cases are represented.

The report returns geometry groups, retained groups, failed or open duties and their exact subjects. Visual inspection of the engineering model can continue when shop or structural evidence is incomplete. The verdict rests on the registered evidence: no key, signature or environment variable takes part, and each native observation is accepted as recorded. Save the review with `--require-publication --output` and commit it with the [status change](design-publication.md#effective-designs); a review with any other verdict fails the publication check. ### Separate two oblique solids before a costly intersection

When broad-phase boxes overlap for two long diagonal articles, project the complete placed solids onto a common direction normal to their nearest faces. Register the exact issued STEP SHA-256, both occurrence names and one or more world directions. The checker includes shape tolerances and a numerical reserve. A positive interval gap gives a conservative lower bound on clearance in that pose. Touching or overlapping intervals leave the question open. A displaced control should lose its separating gap.

```json
{
  "schema": "agent-frc/placed-separation@1",
  "stepSha256": "FULL_SHA256_OF_ISSUED_STEP",
  "requiredClearanceMm": 0.1,
  "pairs": [{"pair": ["Left guide", "Moving shoe"], "axesWorld": [[-1, 1, 0]]}]
}
```

Run `python PLUGIN/scripts/placed_separation.py ASSEMBLY.step PLAN.json`. Copy the plan's `pairs` into the same issue's `projectedSeparationAxes` in its mechanical-readiness study to repeat the projection during the whole-assembly scan. That scan uses its registered contact tolerance. A proven gap skips the expensive common-volume operation for that pair. Commissioned connections still receive an independent distance measurement. Follow other pairs, moving positions, attachment and loaded function through their usual checks. Preserve any conflicting native evidence and investigate it on the same installed bodies.

For a drawing-backed modeled screw in a smooth pilot, check any intentional common against its finite permitted region. [Locate an intentional thread fit](spatial-fits.md).
